# 「探すクエスト」機能 企画メモ

検討日: 2026-09-21
状態: 企画段階。実装は未着手。チームでの採用可否を相談したい。

## 背景・課題意識

- 既存の置き換えダイエットアプリに新機能を追加する形で検討
- 当初「便利さ」路線(AI提案、データ分析での最適化など)を検討したが、既視感が強く不採用に
- 「便利」ではなく「楽しさ」を軸にする方向に転換

## 着目した課題

今のアプリは「レシピを提案すること」までしかやっておらず、**「その材料、実際どこで買うの?」という後工程が完全に手つかず**だった。置き換え食材を実際に入手する段階(どこに売っているか分からない不安・面倒)に着目し、そこを解消しつつゲーム化する。

## 技術的な前提(先に確認済みのこと)

- スーパーの横断的なリアルタイム在庫API(イオン・西友などを横断して在庫が分かるもの)は現状存在しない
- 個別のPOSシステム(Smaregi等)は店舗運営者向けで、外部の一般開発者が使えるものではない
- → 正確な在庫情報は諦め、**ユーザー投稿による集合知**でカバーする設計にした

## コア機能: 「探すクエスト」

1. アプリが今日の置き換え候補を提案(オートミール/豆腐バー/こんにゃく麺など)
2. 近隣スーパーを地図表示(Google Maps API等)
3. ユーザーが探しに行き、見つけたら写真投稿→発見報告としてポイント獲得
4. 未発見の場合も記録し、次回の提案に反映

## クエストのバリエーション

- **選択式クエスト**: 候補のうち1つ見つければOK(ハードルを下げる)
- **レア食材クエスト**: 発見報告が少ない食材は高ポイント
- **エリア制覇クエスト**: 誰も報告していない店舗で発見→「開拓者」バッジ
- **連続クエスト**: 継続日数に応じた達成
- **リベンジクエスト**: 過去に見つからなかった食材の再挑戦

## データ分析の使いどころ

- 店舗×食材の発見率マップ(地域ごとの傾向可視化)
- 個人の「得意/苦手な食材」の分析→成功しやすい提案の優先
- クエストの難易度バランス調整(簡単なものとチャレンジ系を混ぜる)

## 未確定・次に詰めるべき論点

- 既存の置き換えダイエット部分の機能範囲・技術スタックとの整合性
- ポイント・称号のUI/UX設計
- 投稿の信頼性担保(適当な投稿への対策、またはゆるく許容する設計にするか)
- ハッカソンデモ用の仕込みデータ準備(初期投稿ゼロ問題への対処)
- MVP優先順位: ①提案 → ②地図表示 → ③発見投稿、を最初のコアとし、ランキング・キャラ演出は後回し

## 検討時点での所感(参考)

- 機能6(食事写真からのカロリー計算)は画像認識の難易度を理由に見送られているが、
  この機能で使う写真投稿は「画像認識」ではなく「発見報告の証拠」としての利用のため、
  技術的なハードルは機能6とは別物(単純な画像保存・表示で済む)
- コールドスタート問題(初期投稿ゼロ)は、今日何度もぶつかった壁と同種の課題。
  仕込みデータでの対処が必要
- 規模としては、今日実装した「提案の多様性チェック」機能と同等かそれ以上。
  3週間のハッカソンの残り時間との兼ね合いを、チームで相談する必要がある
